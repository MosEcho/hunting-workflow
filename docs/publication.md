# 公开范围与发布过程

公开库的输入白名单包括：自有代码、方法文档、空模板、合成数据、测试和 CI。
真实研究工作区、账户资料、原始取证、未公开报告与外部软件环境留在各自私有位置。

## 发布检查

```sh
python3 -m unittest discover -s tests -v
python3 tools/check_docs.py
python3 tools/audit_public.py --manifest out/publication-audit.json
```

先建立 `out` 目录或使用已存在的输出位置。
审计限定在当前仓库，按目录/文件白名单读取 Git 发布候选；检测软链接、异常二进制、大文件、凭据模式、个人路径及非示例地址等。
检测输出只列类型和位置，不回显匹配值。它是辅助检查，不是敏感内容不存在的证明。

发布前人工确认：文件来源、未公开研究内容、授权/披露状态、个人信息、截图与样本，以及许可证范围。
生成的研究包即使通过材料检查，也不能因此加入公开源码仓库。

## 源码包

```sh
python3 tools/package_source.py --output out/hunting-workflow-0.1.0.zip
```

源码打包先运行发布审计，再按同一候选清单写入真实文件；不包含 `.git`、本地生成的 `out` 或个人工作区链接。
包内 `RELEASE-MANIFEST.json` 记录源码相对路径、长度与 SHA-256。
源码包与 `case export` 产生的研究材料包是两种不同产物。
