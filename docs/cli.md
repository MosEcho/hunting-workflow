# 命令行

从完整仓库运行 `python3 run.py`；可选安装后将其替换为 `hunting-workflow`。

| 命令 | 作用 |
|---|---|
| `demo --output DIR` | 跑资产、完整/缺项案例、报告与 ZIP 的离线演示 |
| `assets normalize INPUT --output DIR` | 导入 CSV/JSON/TXT，归一化与去重 |
| `case check CASE_JSON [--json]` | 检查结构、证据、引用、缺项与人工审阅条件 |
| `case build CASE_JSON --output DIR` | 生成有明确状态的材料草稿 |
| `case export GENERATED_DIR --output ZIP` | 核对产物哈希并导出实体附件 |
| `--version` | 显示版本 |

## 退出码

- **0**：操作成功。对 `case build` 仅表示写出草稿，对 `case check` 表示可以进入人工报送前审阅。
- **1**：输入/输出错误，或演示自身预期失败。
- **2**：`case check` 有缺项/需要核对/合成阻断；或资产整理有被拒绝的行。

`demo` 内部确认“完整示例材料齐全、合成数据不可真实报送、缺项示例确有缺项”后返回 0。
因此运行演示成功和真实案例就绪是不同结果。

## 常见错误

- 输出已存在：使用新的输出路径，已有产物保留为独立版本。
- 证据摘要不匹配：回到原始证据核对变更原因，再更新记录；不要为通过检查直接替换摘要。
- 证据路径越界或为链接：在案例目录内准备明确的实体证据副本。
- JSON 字段未知或类型不符：对照 Schema，检查拼写与布尔值类型。
- 安装后的 `demo` 找不到示例：示例位于完整源码仓库，可用 `--examples PATH` 指定仓库内 `examples`。

所有运行时命令均在本地处理输入文件，不会启动服务、执行请求或提交平台表单。
