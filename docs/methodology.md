# 从实践提炼的通用方法

流程的价值来自可追溯的输入、判断与产物。每一步都保留未确认项，避免把上一阶段的数量或标记当成下一阶段的事实。

| 阶段 | 输入 | 输出 | 继续条件 | 停止或回退条件 |
|---|---|---|---|---|
| 明确对象与范围 | 产品线索、研究目的、具体测试条件 | 产品/版本、范围来源、预期权限 | 研究对象与可接触范围明确 | 范围不清或无法获取环境 |
| 收集与整理资产 | 已有导出、文档、人工线索 | 去重台账、出处、身份待确认项 | 能追溯产品与实例来源 | 只有标题命中、归属冲突 |
| 建立对照与候选 | 源码/环境、角色、合成对象 | 候选根因、正常/异常行为对照 | 异常具有可解释的安全边界 | 仅页面可见、状态码或正常功能 |
| 原创性比较 | 产品、根因、端点、版本 | 检索记录、相似问题对比 | 有人工比较及保留意见 | 同根因已公开、证据不够 |
| 最小验证 | 候选、明确环境与具体范围 | 原始请求响应、实际影响、清理记录 | 结果可复现且与断言对应 | 需要无范围的数据访问或产生不可控影响 |
| 证据审阅 | 原文、版本、断言、实例记录 | 证据索引、缺项与矛盾清单 | 关键事实有证据，推断有标记 | 字节损坏、引用缺失、结论超出证据 |
| 准备报送 | 已复核事实、平台当前要求 | 字段草稿、报告、附件清单 | 人工确认版本、脱敏与表单 | 将历史经验当现行规则、材料未齐 |
| 修订与跟踪 | 回执、评审意见、新证据 | 新版本、变更记录、实际状态 | 状态有平台回执或明确记录 | 仅凭生成成功就标已受理 |

## 核心区分

1. **资产命中、版本匹配、验证受影响**是三个状态。
2. **IP/服务、部署实例、使用单位**是三个统计维度。
3. **原始观察、静态支持、已验证结论**需要分别标注。
4. **生成成功、材料完整、进入人工审阅、平台受理、最终评级**需要分别记录。
5. **文件/哈希一致**是完整性检查，无法代替业务语义审阅。

## 可以复用的决策记录

每次改变结论时记录：原判断 → 触发证据 → 对照方法 → 新判断 → 仍未确认的内容。
保留旧版本和变更原因，避免新的结论覆盖掉旧证据的时点。

本项目只自动化资产整理、记录校验与材料草稿。研究、验证和平台判断仍需要相应环境及人员完成。
