# Contributor and agent instructions

Read README.md and docs/data-model.md before changing the implementation.

- Keep runtime commands offline and independent of any personal workspace, account, LLM, installed browser or scanner.
- Use only fictional products, example domains and documentation addresses in tracked examples and tests.
- Treat imported asset identity, impact, authorization and originality as assertions requiring human review.
- Keep synthetic examples visibly labeled. Never turn a successful build into a platform acceptance claim.
- Preserve evidence bytes and verify references/digests. Reject out-of-case paths and symlinks.
- Update schemas, examples and documentation when changing the data model.
- Run unit tests, tools/check_docs.py and tools/audit_public.py before publishing.
- Add boundary and negative tests when changing evidence validation, export or readiness semantics.
- Keep generated reports, real cases and credentials outside tracked source. Do not import data from surrounding directories.
